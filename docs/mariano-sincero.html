2. Qué NO almacena MIIA

  • Mensajes de WhatsApp: NO se guardan en disco ni en base de datos. Solo se mantienen temporalmente en RAM para contexto de la conversación activa. Al reiniciar el servidor, se pierden.
  • Audios/imágenes/videos: NO se almacenan. Se procesan en memoria y se descartan.
  • Contraseñas: NO existen. La autenticación es vía Google OAuth (Firebase Auth).
  • Datos de tarjeta de crédito: NO pasan por MIIA. Los pagos los procesa Paddle (PCI-DSS compliant).
  • Conversaciones de otros usuarios: cada tenant está completamente aislado.

4. Seguridad técnica

Encriptación

  • En tránsito: HTTPS/TLS en todas las conexiones (Railway fuerza HTTPS)
  • En reposo: Firebase Firestore encripta automáticamente con AES-256 (Google Cloud)
  • Sesiones WA: Encriptadas con AES-256-CBC antes de guardar en Firestore
  • Backups: Encriptados con AES-256-CBC antes de descarga

Autenticación

  • Firebase Auth con Google OAuth 2.0
  • Tokens JWT verificados en cada request al backend
  • verifyTenantAuth: usuario solo accede a su propio uid
  • verifyAdminToken: solo emails en ADMIN_EMAILS

Firestore Security Rules

  • Cada usuario solo lee/escribe sus propios documentos
  • Colección conversations: allow read, write: if false — bloqueada desde frontend
  • Audit logs: solo lectura por el propio usuario, escritura solo backend
  • Default deny: todo lo no explícitamente permitido está bloqueado

Anti-detección WhatsApp

  • Contact Gate: cascada 8 pasos — MIIA no existe sin trigger
  • Rate Limiter: 5 niveles, máximo 250 msgs/día
  • Human Delay: delays contextuales (lectura + typing + ocupado)
  • Night Mode: auto-sleep 22:15-23:05
  • Read Receipts Selectivos: contactos ignorados = ticks grises
  • Reacciones: 30% (no 100%)
  • Split Casual: 30% de respuestas medianas se parten

7. Riesgos conocidos y mitigaciones

RiesgoSeveridadMitigación
WhatsApp puede banear cuentas que usan Baileys Alto Rate limiter, human delays, anti-detección completo, Dual-Engine con auto-switch
Conversaciones en RAM se pierden al reiniciar Medio Contexto se reconstruye parcialmente desde Firestore. Feature de persistencia planificado.
API keys de Gemini expuestas si Railway se compromete Medio Keys en variables de entorno (no en código). Pool de 17 backup keys con rotación.
Firebase Admin SDK bypasea security rules Medio Backend nunca lee mensajes de otros usuarios. Rules protegen acceso frontend. Contadores agregados para admin.
Meta prohibió chatbots IA terceros (oct 2025) Alto MIIA es indetectable. Anti-detección completo. Plan B: canal propio de mensajería (P9.1).

9. Compromisos de MIIA

  • El admin (Mariano) NUNCA leerá mensajes o conversaciones de ningún usuario.
  • Los datos de un usuario NUNCA serán visibles para otro usuario.
  • Los datos NUNCA se venderán a terceros.
  • Cada usuario puede eliminar su cuenta y todos sus datos en cualquier momento, sin intermediarios.
  • Este informe se actualizará con cada cambio relevante en el manejo de datos.
  • Se generará un informe de privacidad semestral para cada usuario (planificado P4.3).
